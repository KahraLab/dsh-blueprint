# DSH Blueprint

写代码之前，产品的流程只存在于脑子里和零散的截图里。Blueprint 把这部分做成能点、能改的东西，再交给编码 Agent 实现。

它是 DeepSeek Harness 的插件，产物是一个可交互的产品原型：多个屏幕、屏幕之间的跳转、每个屏幕的空/加载/错误状态，以及一份跟着原型走的设计语言。

## 问题

做一个新产品，最容易返工的地方不是代码，是对「这东西到底怎么用」的理解。口头描述、画几笔、做一版静态稿，都要靠对方在脑子里补全跳转、状态、边界。补出来的版本不一样，代码就写歪了。

现有工具各有缺口：设计稿是静态的，走不通；白板能画流程，但不是真界面；让 AI 一句话生成网页，改不动，也留不下规范。

## 做法

Blueprint 提供一个工作台：左边是屏幕与流程，中间是画布，右边是属性和设计令牌。

- 和 AI 对话生成第一版，之后用聊天、点选元素留言、直接拖拽三种方式改。
- 一个屏幕可以有多个状态：默认、空、加载、错误。状态只存相对基础界面的差异。
- 屏幕上的一块可以连到另一个屏幕，也可以连到没有界面的动作，比如发邮件、等审核、支付回调。
- 设计语言是一个 `DESIGN.md` 文件：正文写规则与范例，文末一个 JSON 令牌块。原型引用它的某个版本，改一处令牌，画布实时跟着变。
- 做完可以导出可交互的 HTML、单张图片，或者把设计文档和设计语言一起交给编码 Agent。

## 为什么做在 DSH 里

DSH 把模型、工具调用、文件读写和界面放在同一个运行时里。插件能直接读写工作区文件、注册模型可调用的工具、把界面挂进主面板，不需要另起一个应用再想办法同步状态。

## 现在到哪一步

规格阶段，还没有插件实现。已经定下来的有：领域模型、编辑器基座、文档的样式与布局模型、设计语言格式、DSH 宿主能力。

一个能占满整页、支持热更新的插件骨架已经跑通，产物 12.8 KiB，放在 `.tmp/scaffold/`，用来证明宿主链路可用。

## 不做什么

- 不做设计作品生成器。产物是产品原型，不是可以直接发布的视觉稿。
- 不做矢量绘图。没有钢笔、布尔运算、蒙版、渐变网格。
- 不做多人协作。第一版只有单人使用。
- 不做代码生成。原型交给编码 Agent，由它按自己项目的工程规范实现。

## 路线

| 阶段 | 交付 |
|---|---|
| M0 | 插件能装上、能占整页，渲染一份写死的设计文档 |
| M1 | 对话生成第一版；模型改文档，画布跟着更新 |
| M2 | 点选元素、直接拖拽、改文字、属性面板 |
| M3 | 设计令牌面板，改一个值全画布生效 |
| M4 | 流程层：屏幕、跳转、状态、总览 |
| M5 | 导出、版本历史、交接给编码 Agent |
