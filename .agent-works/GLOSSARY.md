# DSH Blueprint 术语表

只收录已定死的领域术语。不含实现细节、不含待议项。

## DSH Blueprint

本插件与产品的名字。一个 AI 原生的产品设计工作台：在动工之前，把整个产品的使用流程做成可走通、可打磨、可交给编码 Agent 实现的高保真蓝图。

## 蓝图 (Blueprint)

本产品的核心实体，也是产物本身：一份可被人和 AI 共同编辑高保真界面的设计文档。它不是设计作品，也不是代码；它是「这个产品怎么用」的具体化，用来在写第一行代码之前对齐判断。一个工作区里可以有好几份蓝图。

## 设计文档 (Design Document)

蓝图在磁盘上的形态：一份由若干屏幕组成、以结构化元素树表达的 JSON 文档，不是图片，也不是代码文本。一个蓝图对应一份设计文档，文件叫 `<id>.blueprint.json`。

## 设计语言 (Design Language)

一套可复用的设计约定与数值：颜色、字体、字阶、间距、圆角、阴影，以及配套的意图说明。它是独立对象，被蓝图按版本引用。

## 屏幕 (Screen)

蓝图中承载一个界面情形的单元，是流程的节点。**屏幕就是画板本身**，不另设画板概念——它是一块画布加流程元数据。

## 状态 (State)

同一屏幕在不同情形下的呈现，例如默认、空、加载、错误。状态以「基础元素树 + 差异」表达，不是完整副本。

## 转移 (Transition)

一个显式对象：源屏幕 + 触发（元素或事件）+ 目标节点 + 条件。屏幕之间不靠元素隐式跳转。

## 动作节点 (Action Node)

流程中没有界面的步骤，例如发送邮件、等待审核、支付回调。它在流程总览里显示为卡片，可连接前后转移。

## 容器 (Container)

能装子元素的图层，也就是带 `layout` 字段的画板或图层。容器分两种：按流向排布子元素的，和让子元素自己管坐标的。一个元素是不是容器，与它是不是画板无关。

## 流向 (Stack)

容器的排列模式：横向或纵向，加间距、内边距、两轴对齐。流向容器里的子元素只排顺序，没有自己的坐标。

## 尺寸三态 (Sizing)

图层的宽和高各有三种取值方式：固定（写死像素）、自动（贴着内容）、填满（占满容器剩下的空间）。只有固定态读取存下来的数字。

## 图层 (Layer)

屏幕内的一个元素节点：文本、形状、图标或图片。图层可以嵌套，形成父子层级。

## 组件 (Component) / 实例 (Instance)

可复用的图层集合（主组件）与被引用的副本（实例）。实例可以局部覆盖样式或内容。v1 只做这一层薄语义。

## 元素树 (Element Tree)

设计文档的骨架：屏幕 → 图层 → 子图层。每一次 AI 编辑都是对元素树的结构化修改。

## 设计 token (Design Token)

设计语言里的最小可复用数值：颜色、字体、字阶、间距、圆角、阴影。图层样式优先引用 token，而不是散落的字面值。

## 编辑补丁 (Patch)

对设计文档的一次结构化、可校验、可撤销的增量修改（新增 / 修改 / 移动 / 删除节点），不是整份重写。

## 工作台 (Workbench)

DSH 里承载画布编辑的界面。和对话并排，就在右侧栏那个面板里：画布、图层、属性都在里面，可从对话侧打开。

## 自由图层 (Free Layer)

脱离自动布局流、以绝对坐标定位的图层。作为受限的第二布局模式存在，不是默认。

## 交付包 (Handoff Bundle)

交给编码 Agent 的产物集合：设计文档、设计语言、以及让实现贴合蓝图的说明。
