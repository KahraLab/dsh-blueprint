# 用户故事与核心路径

> 这份文档定的是「人怎么用这份产品」，不是功能清单。之后每加一个功能，都要能指回下面某条路径的某一步；指不回去，就先别加。

## 一句话

产品的价值只发生在一个循环里：**说一句 → 画布上看见 → 指过去 → 改动落下**。循环外面只有两件事：起一份蓝图，和把它交出去。所有设计都服务这个循环，别让它断。

## 谁在用

| 角色 | 什么时候打开 | 想拿走什么 |
|---|---|---|
| Design Engineer（主） | 有个产品的想法，想先和 AI 把界面和流程摆出来，确认没漏状态和分支，再开工 | 一份能走通、能量到细节、能直接交给编码 Agent 的蓝图 |
| 产品 / 创始人（次） | 要把需求讲清楚，但不写代码 | 让 AI 画出可点的界面，指着说哪里不对 |
| 编码 Agent（隐形） | 实现阶段读工作区里的文件 | 不靠对话历史也能知道每一屏长什么样、状态和流程怎么走 |

前两个角色用同一个面板；第三个角色不打开界面，只读文件。任何「只在对话里说过、没落进文件」的信息，对第三个角色都是丢失的。

## 核心路径

三条路径按使用频率排：路径一是第一次成功，路径二是主旅程，路径三是之后每天的使用。

### 路径一：五分钟第一屏

目标：**从打开 DSH 到看见第一屏，不超过五分钟，中间不需要读任何说明。**

| # | 用户动作 | 应该看到 | 断在这里就是失败 |
|---|---|---|---|
| 1 | 打开 DSH，点左侧栏「蓝图」 | 设计入口页：中央提示词输入、工作区选择，输入框底部「项目蓝图库」 | 落在 Dashboard；空白、转圈、报错 |
| 2 | 选工作区，输入「做一个 SaaS 登录页」，发送 | 所选工作区里开出一个普通 Agent 会话，左侧工作区下出现这一行；此时可以还没有蓝图文件 | 要再按一次发送；会话没归到任何工作区 |
| 3 | 在会话里让 AI 开始画 | AI 创建工作区的 `<id>.blueprint.json`，右侧蓝图编辑器自动打开；左上显示「未命名蓝图」和 id，空画布给一句引导 | 只回话不建文件；右栏空白；打开的是别的蓝图 |
| 4 | 点一下按钮 | 元素高亮，右侧属性栏出现尺寸、颜色、文字 | 点不中；属性栏空着 |
| 5 | 在对话里说「这个按钮换成描边」 | AI 回话时画布已经变了；AI 复述改了哪一处 | 要刷新才看见；改错地方 |
| 6 | 关掉 DSH 再打开，从左侧工作区点回刚才的会话 | 会话还在；右侧编辑器回到这个会话的蓝图，画到刚才那一屏 | 改动丢了；右栏回到别的蓝图 |

这条路径上不允许出现：保存按钮、模板选择、连续弹窗、要用户记命令。也不允许因为发送了一条提示词，就自动创建空白蓝图。

### 路径二：一份蓝图走到交付

八个阶段，每个阶段都要有「看得见的证据」，否则不算完成。

| 阶段 | 用户想完成 | 看得见的证据 | 结束条件 |
|---|---|---|---|
| 起头 | 定下要做的是什么产品 | 一个归属所选工作区的普通会话；需要画时创建第一份蓝图，右侧编辑器打开 | 会话可以继续，蓝图按需创建 |
| 第一屏 | 看见第一个界面 | 一屏带真实排版和文字的界面 | 用户说「对，大概是这样」 |
| 铺开 | 把主要页面都摆出来 | 多块画板并排，每块是一屏 | 主要页面都在 |
| 连流程 | 确认页面之间走得通 | 热区有去向，流程总览里屏和线连成网 | 关键路径上没有断点 |
| 补状态 | 补上空、加载、错误、无权限 | 每屏能切换状态，看到差异 | 极端情况也有画面 |
| 统一语言 | 让所有屏看起来是一个产品 | 颜色、字号、间距来自同一套令牌 | 改令牌，所有屏一起变 |
| 走查 | 像用户一样点一遍 | 点热区从一屏走到下一屏 | 走完主流程不卡住 |
| 交付 | 把蓝图交出去 | 导出件可点可看；编码 Agent 能读文件直接实现 | 对方照着做得出来 |

### 路径三：回来接着改

目标：**隔了几天回来，十秒内回到上次的工作位置，接着改。**

| # | 用户动作 | 应该看到 |
|---|---|---|
| 1 | 打开 DSH，从左侧工作区点回上次的会话 | 会话原样打开，右侧编辑器回到这个会话的蓝图 |
| 2 | 回到上次那一屏 | 上次的缩放和位置还在 |
| 3 | 说「首页卡片改成三列」 | 只改这一处；历史里留着昨天的版本 |
| 4 | 发现改坏了 | 撤销一次回到修改前；或从历史恢复某一版 |

想浏览别的蓝图时，从左侧「蓝图」进设计入口页，再点输入框底部「项目蓝图库」进 Dashboard。

## 不分功能的硬规则

这些是路径能不能走通的前提，不属于某个具体功能：

- **画布是文件的影子。** 无论改动来自对话、命令行还是用户自己，编辑器都在一秒内自己更新，不需要刷新、重启。
- **蓝图是文件，不是消息的副作用。** 发送第一条提示词只开普通会话；只有确实创建了 `.blueprint.json`，编辑器才有东西可显示。
- **会话归工作区。** 从设计入口开始的会话和普通会话没有区别，归属哪个目录由入口页的工作区选择决定，不另造蓝图专用目录。
- **没有保存这个动作。** 停手就落盘；标题栏只说「正在保存 / 已保存 / 保存失败」，失败要能重试。
- **一次修改是一个撤销单元。** AI 的一批修改、用户的一次拖动，撤销一次回到修改前；撤销栈人和 AI 共用。
- **失败必须给下一步。** 不能只显示「失败了」：要么让用户重试，要么说清换个说法，要么保留半成品让人继续改。
- **编辑器不抢注意力。** AI 干活时用户还能拖别的元素、切屏、看历史；不弹模态、不锁滚动。
- **对话是嘴，画布是眼。** 会话开始后，自然语言只走 DSH 对话；设计入口页的输入框只负责开启会话，不是第二个聊天窗口。
- **文案短、说人话、中英成对。** 界面里不出现「这个 / 还没 / 打不开」这类拖沓说法；所有字符串走 i18n。

## 用户故事

### 必须有（v1 缺任何一条都不成立）

**U1 从设计入口开始，并在 Dashboard 管理蓝图**
作为使用者，我想从左侧「蓝图」直接描述要做的东西，之后又能在一个地方管理已有的蓝图，以便不用记文件名。
验收：设计入口页有工作区选择器和中央提示词框，选择器列出已有工作区、标出当前项，并能添加工作区；新工作区直接出现在左侧列表；输入框底部「项目蓝图库」进 Dashboard，Dashboard 标题写明「<工作区文件夹名> 的蓝图」；发送后所选工作区里出现一个普通 Agent 会话，左侧会话列表能看见它，此时不要求已有蓝图；Dashboard 显示当前工作区的全部蓝图；创建蓝图会写出 `<id>.blueprint.json` 并打开右侧编辑器，编辑器左栏顶部显示展示名（默认「未命名蓝图」）和等宽灰字 id；重开会话回到它自己的蓝图。
边界：发送提示词本身不创建蓝图；Dashboard 打开蓝图时借用普通会话，没有就新建一个空白会话，再打开右侧编辑器。

**U2 空画布教人第一步**
作为第一次来的人，我想空画布告诉我该干什么，以便不用读文档。
验收：空文档中央有一句引导，给出一个可以直接照着说的例子，比如「做一个 SaaS 登录页」。
边界：一旦有内容，引导就消失，不再出现。

**U3 一句话生成第一屏**
作为使用者，我想在对话里描述一个界面就得到一屏，以便不用从零拖元素。
验收：生成的屏幕有明确画板尺寸、真实文字、合理层级；布局用排布而不是一堆绝对坐标；生成完自动切到这屏。
边界：一次生成一屏；整条流程（多屏）放下一轮。

**U4 指着说改**
作为使用者，我想先点中元素再说「这个改大一点」，以便不用描述它在哪。
验收：AI 能读到当前选中的元素；改动只落在这个元素上；一次回复一批改完；画布立即更新。
边界：选中多个时 AI 要反问改哪个，不猜。

**U5 对话里改结构**
作为使用者，我想不指元素也能说「加一个第三方登录」「整页换成深色」，以便处理跨越很多元素的改动。
验收：AI 读懂整屏或整份文档的范围；改动落在文档里；回复说清动了哪些地方；一次改完可一次撤销。
边界：AI 没把握时先问一句，不整份重写。

**U6 直接动手**
作为使用者，我想拖一拖、改个数字就把细节调好，以便不用每件小事都找 AI。
验收：拖动、缩放、改文字、改颜色、调层级都立即生效；松手后落盘；改动可撤销。
边界：流向容器是默认，自由定位是受限的第二模式。

**U7 改动不会丢**
作为使用者，我想关掉编辑器、切会话、等 AI 改完再回来都还在，以便信任它。
验收：任何成功写入都能读回；AI 和用户同时改时不丢正在进行的操作；保存失败有可见提示和重试。
边界：不做「冲突了请手动合并」这种界面。

**U8 加屏与切屏**
作为使用者，我想加第二屏、第三屏并在里面切换，以便把产品铺开。
验收：新屏自动命名、可改；画板和图层都能切换；视图位置按屏记住。
边界：不做自动排版屏幕。

**U9 屏幕之间连得通**
作为使用者，我想让热区指向另一屏，并在总览里看见关系，以便确认流程没断。
验收：一屏的热区能指向目标屏；总览里屏是节点、转移是连线；点节点能进对应屏。
边界：怎么连（拉线、对话还是总览）由「流程层」那张票定，这里只要求结果。

**U10 每屏不只一个样子**
作为使用者，我想给一屏加空、加载、错误这些情况，以便别在实现时才发现漏了。
验收：状态只存与基础的差异；能预览和切换状态；切换时布局不塌。
边界：状态不做成独立副本。

**U11 一套设计语言管所有屏**
作为使用者，我想让所有屏共用一套颜色字号，以便改一处全变、看起来像一个产品。
验收：能引入一份 `DESIGN.md`；生成时按令牌出样式，不写字面色值；改令牌后所有屏同步变。
边界：不做设计系统的发布、分发、版本市场。

**U12 像用户一样走一遍**
作为使用者，我想点着热区从首页走到下单完成，以便确认整个流程真的能走。
验收：走查模式点击热区跳屏；没连的去向给提示；退出回到编辑原处。
边界：不做录屏、不做全屏演示模式。

**U13 交得出去**
作为使用者，我想把蓝图导出成能看的文件和能实现的说明，以便交给编码 Agent 或同事。
验收：导出文件夹含可点击 HTML、每屏 PNG、设计语言、实现说明和验收清单；完全离线可用；编码 Agent 只读文件就能实现。
边界：不做 PDF、分享链接、代码生成。

**U14 改坏了能回去**
作为使用者，我想看历史、回到某一版，以便放心试错。
验收：时间线显示每次修改的时间和原因；可预览；恢复前自动给当前拍快照。
边界：不做版本 diff、不做分支。

### 应该有（下一轮）

- **U15 元素意见**：选中元素留一句话，AI 只改这里，改完标记已处理。入口和归属由「蓝图编辑器的布局」定。
- **U16 蓝图管理**：改名、删除、复制。名字在 Dashboard 里就能改。
- **U17 一次生成一条流程**：说「做一个注册到下单的流程」，产出多屏加转移加状态。
- **U18 从蓝图沉淀设计语言**：把一份蓝图里的颜色字号抽成 `DESIGN.md`，下一份蓝图复用。
- **U19 回来就在原地**：视图、屏、缩放恢复到离开时；多蓝图时能搜索。
- **U20 大蓝图也顺手**：二十屏、每屏上百图层时拖拽和切屏不卡；打开 Dashboard 和编辑器不被缩略图拖慢。

## 明确不做的路径

- 右侧编辑器里再嵌一个聊天框。设计入口页的输入框只负责开启会话，不是持续聊天的窗口。
- 为蓝图另造一种特殊会话。蓝图一律通过 DSH 普通会话创建和修改。
- 模板库、组件市场、设计系统商店。
- 多人实时协作、分享链接、评论他人。
- 从蓝图生成代码。交给编码 Agent 自己实现。
- 矢量绘图、动效时间轴。

## 这份文档怎么验收

找一个没参与讨论的人，只给产品，不解释：

1. 五分钟内能不能说出这个产品是干什么的；
2. 能不能自己走完路径一；
3. 走完之后能不能指出至少一处「这里还没想清楚」。

三条都成立，故事就算写清楚了；卡在第几步，就说明那条路径那一步是空的。

## 和里程碑的关系

| 路径阶段 | 里程碑 |
|---|---|
| 起头、第一屏、指着说改、加屏 | M3 生成与聊天迭代 |
| 连流程、补状态、走查 | M5 流程与状态 |
| 统一语言 | M4 设计语言 |
| 交付、版本历史 | M6 交付 |

起头和直接动手这两段由 M1、M2 承担；表里只列还没有着落的部分。
