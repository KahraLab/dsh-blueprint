# 插件架构与存储

> 界面、后台、磁盘三方怎么分工；文档以谁为准；文件怎么摆；历史怎么留。

## 一句话

界面只能读，后台负责写；文档的权威副本在后台，落成工作区文件；界面通过平台连接层调后台的路由；每次 AI 动手前自动留一张快照。

> 这份规格写终态，不记实现差口。现在到哪一步看地图的「实现进度」。

## 三方职责

| 角色 | 做什么 | 不做什么 |
|---|---|---|
| 界面（client 半） | 画布渲染、交互、把改动打成补丁发出去；缓存一点界面状态 | 不写文件，不直接改磁盘 |
| 后台（host 半） | 持有文档、校验补丁、写盘、拍快照、注册模型可调用的工具 | 不做界面渲染 |
| 磁盘（`.dsh-blueprint/`） | 唯一持久化位置，可被 git 跟踪，可被编码 Agent 读 | 不存运行态 |

## 为什么界面不写盘

平台只给界面读工作区的权限，没有写。这不是缺陷，是约束带来的好处：**写盘只有一条路**。校验、快照、防冲突都只需要在一个函数里做，不用两头对账。

后台暴露一条统一的修改入口：

```
apply(projectId, ops, baseRevision) → { revision, appliedAt }
```

模型改文档、用户拖图层、导入设计语言，全部走这一个人口。谁先谁后由后台排队，不并发写。

## 传输

后台注册自己的路由，界面用 `connection.fetch` 调用。鉴权由平台的连接层统一处理：同源放行，跨源 403，不带凭证 401。

| 路由 | 作用 |
|---|---|
| `GET /blueprint/projects` | 列出原型 |
| `POST /blueprint/projects` | 新建原型 |
| `GET /blueprint/projects/:id` | 读文档全量 + 当前 revision |
| `POST /blueprint/projects/:id/patch` | 应用补丁（带 `baseRevision`） |
| `POST /blueprint/projects/:id/snapshot` | 手动快照，可命名 |
| `GET /blueprint/projects/:id/history` | 快照列表 |
| `POST /blueprint/projects/:id/restore` | 回到某个快照（先给当前状态拍一张） |
| `POST /blueprint/projects/:id/assets` | 上传图片，返回文件引用 |
| `GET /blueprint/icons` | 图标目录与已下载集合 |
| `POST /blueprint/icons` | 下载一个图标集 |
| `GET /blueprint/icons/set?prefix=` | 一份集合的完整数据 |
| `GET /blueprint/icons/index?prefix=` | 一份集合的名字索引 |
| `* /blueprint/languages/...` | 设计语言的同构路由 |

`baseRevision` 对不上时，后台拒掉这次补丁并回最新文档。界面拿到最新版后重放自己的改动；重放不了就提示冲突，不猜。

## 磁盘布局

```
<workspace>/.dsh-blueprint/
├── current.json          # 面板当前打开哪个原型
├── design-languages/
│   └── harbor/
│       ├── DESIGN.md
│       └── history/
│           └── 1.md
└── prototypes/
    └── checkout/
        ├── checkout.blueprint.json
        ├── assets/
        │   └── 7f3a9c.png
        ├── assets.json
        └── history/
            ├── index.json
            └── 0001-2026-10-28T13-40-12.json
```

- **没有总索引文件**。项目列表就是目录列表，`<id>.blueprint.json` 里存标题、创建时间这些元信息。少一个要和目录对账的文件。
- **文件名是 `<目录名>.blueprint.json`**，目录名就是 id，文件跟着目录走。单个文件拷出去也认得出这是蓝图文档。
- **目录名就是 id**，创建后不再改。改标题只改文件里的 `title`，不动目录——避免因为改名让 git 历史断掉、让引用失效。
- id 只允许小写字母、数字、连字符，防止拼路径时出问题。新建原型时由 nanoid 生成 10 位小写短 id，标题默认「未命名蓝图」，用户之后改标题不动 id。
- **当前项目记在 `current.json`**，画布切换原型时更新。命令行按「显式 `--project` → 当前项目 → 唯一原型」定位，不靠猜。
- **文件带格式版本号**。读到比插件新的版本时拒绝打开，并说明是插件旧了；不按旧规则猜新字段。

## `<id>.blueprint.json` 的骨架

```json
{
  "schema": 3,
  "id": "checkout",
  "title": "结算流程",
  "createdAt": "2026-10-28T13:40:12Z",
  "revision": 12,
  "updatedAt": "2026-10-28T14:02:10Z",
  "updatedBy": "cli",
  "document": { "frames": [], "layers": [] }
}
```

- `schema` 是文件格式版本，当前为 3。
- `revision` 是每次成功写入后递增的版本号，写入方带 `baseRevision` 做冲突检测；内容没变的提交不落盘、不涨版本。
- `document` 就是元素树（屏幕=画板，图层带盒模型与排布）；它的字段细节在「元素树与样式的表达方式」里。
- 设计语言引用、流程层字段随各自里程碑加入；在那之前文件里没有它们，读的时候不假设存在。

## 历史快照

- **AI 每次动手之前，自动拍一张**，标 `auto:model`。
- **用户可手动命名一张**，标 `manual:<名字>`，永久保留。
- 自动快照保留最近 100 张，超出的按时间删。手动的一张不删。
- 恢复快照时，先把当前状态拍一张，再载入旧版——恢复本身也可撤销。
- 快照是整个文档的完整副本，不是 diff。原型文件不大，简单比聪明可靠。

`history/index.json` 只记元信息：序号、时间、原因、文件名。快照内容各自独立成文件。

## 图片素材

- 上传的图片复制进 `assets/`，文件名用内容哈希加扩展名，同样的图不会存两份。
- `assets.json` 记来源：`{ "7f3a9c.png": { "from": "/Users/.../login.png", "addedAt": "..." } }`。来源只是备注，不参与渲染。
- 文档里只引用文件名，不写绝对路径。整个目录拷走就能用。

## 图标素材

- 图标集是用户自己攒的素材，不是插件的代码：下载到全局 `~/.dsh/blueprint/icons/`，所有工作区和原型共用；插件本体不打包任何图标。
- 三份文件：`catalog.json`（有哪些集合、许可、总数，一周缓存）、`sets/<集合>.json`（完整数据，来自 `@iconify-json/<集合>`）、`sets/<集合>.index.json`（只有名字，搜索用）。
- 文档里只写 `iconSet` + `iconName`。写入时后台从库里取图、清洗掉脚本与事件属性，再补进节点的 `svg`——所以文档自身能渲染、能交接，换台没下载过该集合的机器也不会空。
- 选择器按需取：先目录，再选中集合的名字，再整份数据；网格只渲染看得见的格子。没下载的集合不预取。
- 目录与下载地址可用环境变量覆盖，离线或测试时不碰网络。

## 写盘方式

先写临时文件，再原子重命名。中途失败不会留下半截文件。

磁盘满、没权限、文件被占用：把错误原样告诉界面，不吞掉，也不写半成品。

## 热更新与重启

- 文档永远从后台重新拉。界面不持有「离线副本」。
- 界面状态（选中的屏幕、画布缩放、面板开合）存 `localStorage`，按项目 id 分开。
- 文字编辑不攒草稿：输入停顿 300ms 就提交补丁。热更新最多丢这 300ms。
- 面板被卸载重挂时，重新拉文档、恢复界面状态，接着干。

## 出错时

| 情况 | 表现 |
|---|---|
| 后台没起来 | 界面进只读模式，顶部一条提示，不假装能存 |
| 补丁被拒（revision 落后） | 拉最新文档，重放改动；重放失败提示冲突 |
| 写盘失败 | 保留内存中的改动，提示原因，可重试 |
| 界面崩溃 | 后台文档不受影响，重开即恢复 |

## 对下游的影响

- **交接给编码 Agent**：读的就是磁盘上这份，不需要额外导出步骤，只需要打包。
- **设计语言升级影响面**：扫所有 `<id>.blueprint.json` 里的 `designLanguage` 引用即可算出。
- **多人协作**：暂时不做。将来要做的话，`apply` 这个唯一入口就是插入协同层的位置。

## 客户端状态

界面状态集中在 `apps/plugin/src/client/store.ts`，一个 zustand store：文档、选中、正在编辑的文字、工具、页签、保存状态都在里面。

- **组件不直接取 store**：画布、属性栏、层级树收的是 props，store 只在面板里读一次再往下传。这样组件还能在无宿主的环境里单独渲染。
- **读写盘不在渲染路径上**：读盘是 `loadDocument(url)`，写盘是 `startSession(url)` 订阅文档变化后防抖 600ms 再 POST。React 里只留一个 effect 负责启动这一对。
- **文档永远是整份不可变替换**：每个动作返回新的文档对象，订阅按引用判断有没有变化。
