# M3 生成与聊天迭代：需求设计与技术方案规格说明书

> 本文档针对 DSH Blueprint 路线图中的核心里程碑 **M3（生成与聊天迭代）** 进行需求定义、架构设计与工程技术落地拆解。
> 核心目标是闭环产品的灵魂循环：**说一句 → 画布上看见 → 指过去 → 改动落下**。

---

## 一、 核心价值与场景定义

在产品设计阶段，用户不需要也不应该通过拖拽几十个矩形和文字框来从零搭建界面。
M3 承担着连接「自然语言会话」与「高保真画布编辑器」的桥梁职责，覆盖两个核心关键阶段：
1. **0 到 1（冷启动）**：一句话生成一屏结构完整、高保真、纯 Flex 盒模型的可用页面。
2. **1 到 N（迭代与微调）**：用户在画布上指点元素，直接在对话或浮层发表修改意图，AI 精准实施局部原子 Patch，不破坏其余结构。

---

## 二、 核心场景 1：从一句话生成一屏（0 到 1）

### 1. 业务交互旅程
1. 用户在 DSH 普通会话中输入：“帮我做一个外卖 App 的订单详情页，要有配送进度、骑手联系卡、商品清单、费用明细以及底部的确认送达和申请售后按钮。”
2. 模型加载 `dsh-blueprint-canvas` 技能，通过 `bp view` 检查当前蓝图状态（若为新画板，计算画板排布偏移位置）。
3. 模型一次性输出符合协议标准的整屏嵌套树结构，通过 `bp apply` 提交原子修改。
4. 画布在 1 秒内无缝渲染出该屏幕，视口平滑居中聚焦到新画板；模型在会话中以 2~3 句话概述页面结构，不输出大段原始 JSON。

### 2. 生成规范与 Prompt / Skill 引导体系

为了防止模型生成“一堆绝对坐标定位的方块”或“丑陋低质的占位图”，技能层必须严格约束以下六大铁律：

#### (1) 画板规格与命名
- **标准画板尺寸**：移动端默认使用标准手机画板 `390 × 844`（iPhone 14/15 规格），桌面端默认 `1440 × 900`。
- **画板属性**：画板自身必须显式设置背景填充 `fills: [{ color: "#F8F9FA", opacity: 1 }]`。
- **语义化命名**：根画板必须命名为明确业务名（如「外卖订单详情页」），严禁使用「画板 1」等自动编号。

#### (2) 纯 Flexbox 排布（StackLayout），拒绝绝对定位
- 整屏自顶向下分为若干容器块，画板根采用 `layout: { direction: 'column', gap: 0, padding: { top: 0, right: 0, bottom: 0, left: 0 }, align: 'stretch', justify: 'start' }`。
- 纵向结构严格按照高保真标准 App 拆解：
  - **状态栏与导航栏（NavBar）**：高度 44~56，横向 `row`，两端对齐 `justify: between`，左右包含图标或操作，中间为标题。
  - **主体滚动内容区（Scrollable Body）**：`sizeW: fill`，`sizeH: hug` 或 `fill`，内部以统一 `gap: 12` 纵向堆叠业务卡片，左右预留 16px 内边距。
  - **业务信息卡片（Card Containers）**：每个卡片（如订单状态卡、配送信息卡、菜品列表卡、费用小计卡）为独立容器，`fills: [{ color: "#FFFFFF", opacity: 1 }]`，`radius: 12`，内边距 `16`。
  - **底部固定操作栏（Bottom Bar）**：`sizeW: fill`，固定高度或贴合内容，横向排列辅助操作与主行动按钮（CTA）。

#### (3) 严格的尺寸三态约束（fixed / hug / fill）
- **文字（Text）**：单行标题/标签使用 `sizeW: hug, sizeH: hug`；需要自适应撑满换行的段落/描述使用 `sizeW: fill, sizeH: hug`。
- **卡片与行容器**：横向铺满设为 `sizeW: fill`；高度随内容自适应设为 `sizeH: hug`。
- **图标与头像（Icon / Avatar）**：严格固定宽高 `sizeW: fixed, sizeH: fixed`（例如 20×20、24×24、40×40）。
- **弹性撑开（Spacer）**：在 Flex 容器中使用一个空的透明容器，设为 `sizeW: fill`，天然实现两端自动弹开。

#### (4) 布局透明容器保护
- 任何仅作为排版分组、无需背景色的容器（例如左右并排的图文行），**必须显式声明 `fills: []`**。若遗漏该字段，系统会默认补上灰色填充，导致界面杂乱。

#### (5) 高保真占位与文案规范
- 严禁出现「Lorem ipsum」、「标题文本」、「按钮 1」等无意义占位符。
- 必须使用真实业务语境的丰富文案：
  - 状态文案：“骑手已接单，正在赶往商家” / “预计 12:45 送达”。
  - 列表项：“招牌黄焖鸡米饭 (微辣+煎蛋) × 1”、“冰镇酸梅汤 500ml × 1”。
  - 金额与明细：“商品小计 ¥32.00”、“配送费 ¥3.50”、“打包费 ¥1.50”、“实付 ¥37.00”。
- 颜色对比与排版层次：
  - 主标题：`#111827`，`fontSize: 16~18`，`fontWeight: 600`。
  - 次要说明：`#6B7280`，`fontSize: 13~14`，`fontWeight: 400`。
  - 强调价格与状态：`#EF4444` 或品牌主题色 `#FF6B00`。
  - 分割线：高度 1，`sizeW: fill`，`fills: [{ color: "#F3F4F6", opacity: 1 }]`。

#### (6) 离线标准图标引用
- 严禁手写拼接内嵌 SVG 字符串。
- 必须声明合法集合与图标名：`{ kind: "icon", iconSet: "lucide", iconName: "chevron-left", width: 24, height: 24 }`。常用图标库涵盖 `lucide` 中的常用导航、状态、动作图标。

### 3. 一次性整屏注入实现（`bp apply`）
生成请求使用单个原子 `insert` 操作，将包含完整子树的树形结构提交：
```json
{
  "reason": "生成外卖 App 订单详情页",
  "ops": [
    {
      "op": "insert",
      "parent": null,
      "node": {
        "ref": "frame_order_detail",
        "name": "外卖订单详情页",
        "width": 390,
        "height": 844,
        "fills": [{ "color": "#F8F9FA", "opacity": 1 }],
        "layout": {
          "direction": "column",
          "gap": 12,
          "padding": { "top": 12, "right": 16, "bottom": 24, "left": 16 },
          "align": "stretch",
          "justify": "start"
        },
        "children": [
          {
            "name": "顶部导航栏",
            "layout": { "direction": "row", "gap": 8, "padding": { "top": 8, "right": 0, "bottom": 8, "left": 0 }, "align": "center", "justify": "between" },
            "fills": [],
            "sizeW": "fill",
            "sizeH": "hug",
            "children": [
              { "kind": "icon", "iconSet": "lucide", "iconName": "chevron-left", "name": "返回按钮", "width": 24, "height": 24 },
              { "kind": "text", "name": "页面标题", "text": "订单详情", "fontSize": 17, "fontWeight": 600 },
              { "kind": "icon", "iconSet": "lucide", "iconName": "phone", "name": "联系商家", "width": 20, "height": 20 }
            ]
          }
          /* 更多业务卡片与子节点... */
        ]
      }
    }
  ]
}
```

## 三、 核心场景 2：点选元素写评论 / 聊天逐条改（1 到 N）

### 1. 交互与上下文闭环机制
在日常迭代中，用户绝大多数操作都是指着界面某处进行微调。核心链路如下：
1. **画布端（Client）**：
   - 用户在画布上单选或框选图层，`selectionStore` 触发变更。
   - 客户端立即向 Host 同步当前选中的目标：`frameId`, `layerId`, `name`, `kind`, `path: ["外卖订单详情页", "底部操作栏", "确认送达按钮"]`，写入本地 `selection.json`。
2. **会话端（Host & DSH UI）**：
   - **点选反馈与指示器**：左侧会话输入框上方展示当前附着的选区胶囊（Selection Capsule），例如：`[聚焦: 确认送达按钮 (按钮)] ✕`，让用户清晰感知上下文已连通。
   - **模型感知**：
     - 当用户发起指令（如“把这个按钮换成深绿色，加粗，加上对勾图标”），模型优先调用 `bp selection` 获取确切目标。
     - 若未命中选区或用户未点选，模型退化为 `bp find --name "确认送达"` 搜索定位。
3. **精准原子 Patch 执行**：
   - 模型针对获取到的 `layerId`，组织最小粒度的修改 op（`set` 修改属性、`insert` 插入图标/子图层、`remove` 剔除多余节点）。
   - 提交 `bp apply`（基于无锁 ID 寻址，无需版本校验，秒级落盘）。
4. **画布端响应与撤销联动**：
   - 前端接收到变更通知后，就地应用 patch，并高亮闪烁修改区域。
   - 该批改动作为单个撤销单元压入撤销栈，用户按 `Cmd+Z` 即可随时回滚。

### 2. 精准修改模型交互示例
用户操作：“把这个按钮改成主色高亮、加上购物车图标”：
```bash
# 1. 探查当前选区
bp selection
# 输出: { "ok": true, "selection": { "layerId": "layer-btn-checkout", "kind": "rect", "name": "结算按钮", "path": ["购物车页", "底部结算栏", "结算按钮"] }, "count": 1 }

# 2. 提交精准 Patch
bp apply <<'JSON'
{
  "reason": "结算按钮改为主色高亮并新增购物车图标",
  "ops": [
    {
      "op": "set",
      "id": "layer-btn-checkout",
      "patch": {
        "fills": [{ "color": "#FF6B00", "opacity": 1 }],
        "radius": 10
      }
    },
    {
      "op": "insert",
      "parent": "layer-btn-checkout",
      "index": 0,
      "node": {
        "kind": "icon",
        "iconSet": "lucide",
        "iconName": "shopping-bag",
        "name": "购物车图标",
        "width": 18,
        "height": 18,
        "fills": [{ "color": "#FFFFFF", "opacity": 1 }]
      }
    }
  ]
}
JSON
```

## 四、 技术实施方案与工程落地点拆解

为保证 M3 高效稳健交付，将其拆解为以下阶段性实施任务卡片（Task Cards）：

### 任务 1: `feat-m3-01` 一句话生成一屏协议与 Prompt/Skill 体系
- **目标**：在 Host 技能中注入完整的生成引导 Prompt 模版与规则约束，确保模型能稳定生成高质量整屏。
- **实施点**：
  - 在 `apps/plugin/src/host/skill.ts` 和 `protocol/guide.ts` 中增强一句话生成的模版指导与少样本（Few-shot）范式。
  - 注入标准画板尺寸（移动端/桌面端）、Flex 排布必须规则、占位数据真实感规则与 `fills: []` 容器隔离规则。
  - 自动化测试校验：编写整屏生成测试用例，校验生成的画板具有合法层级、无非法属性、图标正常解析。

### 任务 2: `feat-m3-02` 画布点选与会话上下文双向联动（Selection Context Injection）
- **目标**：打通用户在右侧画布的点选动作与左侧会话上下文的无缝流动。
- **实施点**：
  - 增强 `selection.json` 的更新实时性与数据丰富度（增加节点尺寸、父级名字、兄弟节点概况）。
  - 在 DSH 客户端界面层面探索选区状态提示，或在技能调用入口强化快速读取当前选区。
  - 处理多选、空选区与失效节点的优雅退化机制（单选直接锁定，多选给出清晰列表追问，空选退化为语义查找）。

### 任务 3: `feat-m3-03` 精准逐条语义改动响应与局部 Patch 引擎
- **目标**：完善局部精准改动的意图识别与操作下发，做到指哪改哪、毫厘不爽。
- **实施点**：
  - 支持快捷批量属性修改（颜色/背景/圆角/边距/字号/排布方向）。
  - 强化 `insert` / `replace` / `remove` 在容器内的精细化索引插入与局部置换。
  - 确保局部改动不影响父级容器既有的 StackLayout 排布与其他兄弟节点状态。

### 任务 4: `feat-m3-04` 画布点选快捷评论气泡交互（Comment/Feedback Bubble）
- **目标**：在画布点选元素上方支持浮现迷你意见输入框，降低用户在画布与聊天框之间来回切换的认知负荷。
- **实施点**：
  - 当选中元素时，在选中框浮动挂载一个小气泡或快捷按钮：“对 AI 说...”。
  - 用户在此输入意见回车，自动拼装带当前图层标识（ID与路径）的提示语直接发送给会话模型处理。
  - 处理完成后在画布上给出操作成功的小反馈动画。

## 五、 质量验收与度量标准

1. **0 到 1 生成质量**：
   - 任意典型业务需求（登录、详情、列表、个人中心、购物车）生成成功率 100%，耗时 < 3s。
   - 生成内容不存在重叠硬写坐标，容器全部使用 Flex 排布，三态尺寸分配准确率 > 95%。
   - 界面无默认灰底残留容器，占位文案全部符合真实业务语境。
2. **局部修改精准度**：
   - 指点修改指令执行成功率 100%，无全局误伤。
   - 单次修改严格作为一个撤销单元，`Cmd+Z` 回滚完全一致。
