# 导出与版本历史

> 导出是给人看的：评审、汇报、存档。交接是给写代码的 AI 看的。两者不是一回事。

## 一句话

导出一个文件夹：能点击走查的 `index.html`、每屏一张 PNG、图片素材。版本历史放在侧边时间线里，能预览、能恢复。

## 导出物长什么样

```
export/<蓝图名>-<年月日-时分>/
├── index.html        可点击走查，双击就开
├── assets/           蓝图里用到的图片，相对路径引用
├── png/
│   ├── tickets.png
│   └── tickets--empty.png
└── README.md         怎么打开、这份导出来自哪个版本
```

## 走查页怎么工作

- 所有屏幕渲染进同一个 `index.html`，一次只显示一个。
- 点画面上的热区，切到目标屏幕。转移上的条件如果满足不了（比如需要登录），就按默认分支走。
- 动作节点（发邮件、等审核、支付回调）没有界面，显示成一张提示卡：「这一步会发送验证邮件」，然后继续。
- 浏览器后退键能回上一屏，因为切换走的是地址栏里的 hash。
- 首屏固定是蓝图里标为「起始屏」的那个；没标就用第一个。
- 不依赖网络，不依赖 DSH，不加载任何外部字体或脚本。

## 图片怎么放

复制到 `assets/`，`index.html` 用相对路径引用。不内联成 base64——图一多文件就几十兆，邮件都发不出去。

单文件看起来诱人，但换来的是传不动。文件夹打包发人，多一步压缩，值得。

## PNG 怎么出

- 每屏一张，覆盖该屏的**每个状态**（默认、空、加载、错误），文件名加后缀区分。
- 2 倍分辨率，够贴文档和评审。
- 在界面里渲染截图，不在后台跑无头浏览器——后台没有浏览器环境，界面本来就已经把画面画出来了。

## 版本历史

存在磁盘上的部分已经定了（AI 改前自动拍、可手动命名、自动的留 100 张）。这一份定的是界面：

**侧边时间线**

- 每条显示：缩略图、时间、原因（「AI 修改」或手动起的名字）。
- 点一条 → 画布进入只读预览，看到那一刻的样子，不动当前文档。
- 预览时有两个按钮：「恢复到这里」和「取消」。
- 恢复前自动给当前状态拍一张，所以恢复本身也能反悔。
- 手动命名的快照永久保留，在列表里带一个名字，不会和自动的混在一起。

v1 不做两版对比（diff）。预览已经够判断「要不要退回去」。

## 导出入口

- 工作台工具栏一个「导出」按钮，选「走查 + 图片」或只导其中一样。
- 导出时显示进度，完成后通过平台的产物卡片交给用户。
- 文件落在工作区根的 `export/` 下，每次新建一个带时间戳的目录，不覆盖旧的。
- 同名蓝图多次导出就是多个目录，用户自己删。

## 和交接包的区别

| | 交接包 `handoff/` | 导出 `export/` |
|---|---|---|
| 给谁 | 写代码的 AI | 人 |
| 目的 | 照着实现 | 评审、汇报、存档 |
| 内容 | 设计语言、蓝图文档、参考实现、实现说明、验收清单 | 走查页、PNG、素材 |
| 什么时候要 | 准备开工时 | 想给别人看时 |

两件事分开，不共用目录，免得「给人看的」和「给 AI 照着做的」混在一起。

## 不做什么

- 不做 PDF。分页排版是另一件事，需要时再说。
- 不做分享链接。发文件更可靠，不依赖对方的浏览器能连到你的机器。
- 不做版本对比。预览够用。
- 不录视频。动效靠走查页自己动。
