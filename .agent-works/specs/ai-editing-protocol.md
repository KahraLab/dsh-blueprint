# AI 编辑协议

AI 通过 `bp` 命令行读取和修改设计文档。用户只使用自然语言与画布，不需要看见命令。

## 原则

1. **所有写入共用一个入口。** 画布拖拽、AI 批量生成和命令行微调最终都提交到同一个 `apply`。
2. **读取与写入都使用 JSON。** 读取按原型、单屏、单元素控制范围；写入使用结构化操作，不引入另一套 DSL。
3. **稳定 id 是身份，语义化名字用于理解。** 修改必须引用 id；名字用于搜索、展示和模型识别。
4. **整批修改原子生效。** 一次 `apply` 要么全部成功，要么不改变文档。
5. **不捆绑 jq。** AI 可以用 bash 中已有的 jq、Python 或 Node 处理 JSON，插件不准备额外运行时。

## 命令面

### 读取

```bash
bp view                         # 原型摘要与每块屏幕的顶层结构
bp view <画板id>                # 单屏完整元素树
bp view <元素id>                # 单元素完整字段
bp selection                    # 用户当前选中的屏幕或图层
bp find [--name 文本] [--kind 类型] [--in 容器id]
bp schema                       # 完整契约：JSON Schema + 行为说明
```

`bp schema` 的 `jsonSchema` 由校验器生成，字段、取值范围和节点/操作形状与写入校验是同一份定义；其余字段说明版本、命名、退出码这些形状之外的行为。

`view` 的输出都带文档 `revision`。不带参数的 `view` 只给鸟瞰信息，不返回整份文档；单屏视图保留识别界面所需的结构、正文、尺寸、排布和关键样式；单元素视图返回完整字段。

所有机器读取命令的 stdout 只输出合法 JSON，不混入说明文字或颜色码。错误写 stderr，进程返回非零。

### 写入

```bash
bp apply < change.json
bp apply --file change.json
```

保留 `add`、`set`、`move`、`rm` 作为单条修改的便捷写法。它们内部必须构造同样的操作并交给 `apply`，不另设写盘、校验或冲突处理路径。

底层操作只有：

```text
insert / remove / set / move / replace
```

## 节点身份与命名

每个屏幕和图层都有：

- `id`：稳定身份，由系统生成。重命名、移动和修改样式都不能改变它。
- `name`：语义化名字，供人和 AI 识别。名字不要求唯一，不参与写操作寻址。

AI 创建节点时必须填写能说明用途的名字，例如「登录页」「手机号输入框」「登录按钮」「商品列表」，不能只填「画板1」「矩形2」。用户手动创建的节点可以继续使用自动编号作为初始名字，之后再改。

`find` 返回匹配节点的 id、名字、类型、所在屏幕和层级路径。只有一个明确候选时 AI 才能直接修改；多个候选且无法从上下文判断时，先向用户确认。

## 当前选择

用户说「这个按钮」「把它改大」时，AI 先调用 `bp selection`，不根据名字猜测。

返回示例：

```json
{
  "revision": 8,
  "selection": {
    "frameId": "frame-a12",
    "layerId": "layer-c56",
    "kind": "rect",
    "name": "登录按钮",
    "path": ["登录页", "表单", "登录按钮"]
  }
}
```

没有选择、选择已失效或存在多个目标时，结果必须明确表达，AI 再决定查找或提问。

选择状态由画布在变化时上报给宿主，存在文档旁边的 `selection.json`。它不进入设计文档，也不增加 `revision`：选中一个元素不是一次文档修改。

## 批量写入

请求格式：

```json
{
  "baseRevision": 8,
  "reason": "登录按钮改蓝色并加大圆角",
  "ops": [
    {
      "op": "set",
      "id": "layer-c56",
      "patch": {
        "fills": [{ "color": "#0D99FF", "opacity": 1 }],
        "radius": 16
      }
    }
  ]
}
```

`reason` 是这次修改的可读说明，用于快照和撤销历史。

生成整屏时，一次 `insert` 可以携带完整子树，不要求 AI 为每个图层单独调用命令。新建节点省略的默认字段由系统按画布现有规则补齐：手机屏幕 390×844，排布对象可以只写 `direction`，其余取默认（竖向、间距 8、交叉轴 stretch、主轴 start）。

`replace` 省略的字段沿用被替换的节点；省略 `children` 时保留原来的子树，写了 `children` 则整棵换掉。

`fills` 写成 `[]` 表示透明。省略 `fills` 才取默认底色（形状 `#D9D9D9`、文字 `#101828`）：只用来做排布的容器必须显式写空数组，否则会带上一块默认灰底。

### 批内临时引用

新节点可以带 `ref`，同一批操作里用 `@名字` 引用它：

```json
{
  "op": "insert",
  "parent": null,
  "node": {
    "ref": "login",
    "name": "登录页",
    "children": [
      { "ref": "title", "kind": "text", "name": "欢迎语", "text": "欢迎回来" }
    ]
  }
}
```

后台负责把 `ref` 换成真实 id。`ref` 只在当前请求内有效，不写进最终文档。

成功响应包含新版本、实际执行的修改和 id 映射：

```json
{
  "ok": true,
  "revision": 9,
  "ids": {
    "login": "frame-a12",
    "title": "layer-t78"
  }
}
```

成功后不强制重新 `view`。只有结果不确定、冲突后重读，或下一步需要更多文档内容时才再次读取。

## 版本与冲突

`revision` 是文档每次成功写入后递增的版本号，不是应用版本，也不是撤销栈的位置。内容没有变化的提交视作空写：不落盘、不产生新版本，也不触发别的面板重载。

例如：

1. AI 读取文档时是第 8 版。
2. AI 准备修改期间，用户拖动了一个图层，画布写入后变成第 9 版。
3. AI 仍带着 `baseRevision: 8` 提交。
4. 后台拒绝整批修改并返回 `REVISION_CONFLICT`，避免 AI 根据旧画面覆盖用户刚做的调整。

AI 遇到冲突必须重新读取，再基于最新文档决定是否重提。AI 写入不自动重试；失败和冲突都不会产生新版本、快照或撤销记录。

## 撤销与重做

- 一次成功的 `apply` 是一个撤销单元。
- 人的画布修改与 AI 修改进入同一个撤销栈。
- 每次成功修改同时留下自动快照；`reason` 作为历史说明。
- 撤销和重做本身也产生新的文档版本，不回退或复用 `revision` 数字。
- 撤销后发生新修改时，清空重做分支。
- 失败或被拒绝的 `apply` 不进入撤销栈。
- 画布提供撤销、重做操作与常见快捷键；AI 默认通过新修改表达意图，不替用户隐式撤销。

## 校验与错误

落盘前至少检查：

- 基础版本是否匹配。
- id 是否存在或重复，`ref` 是否有定义。
- 字段名、字段类型、节点种类是否合法。
- 父容器是否存在，移动是否形成自包含或循环。
- 尺寸、颜色、排布等字段是否符合文档模型。
- 修改后的整份文档是否通过完整性校验。
- 请求里有没有契约之外的字段。

任何一条失败，整批不落盘。契约之外的字段整条操作拒绝，不静默忽略：写错字段名的修改是坏请求，不是部分修改。错误采用结构化的机器可读信息，至少包含错误码、失败操作下标、目标、字段和修复提示。

退出码：

| 退出码 | 含义 |
|---|---|
| 0 | 成功 |
| 2 | `USAGE`（命令或请求用法不对）或 `VALIDATION_FAILED`（操作没通过检查） |
| 3 | `REVISION_CONFLICT`（基础版本对不上） |
| 4 | `NOT_FOUND`（id 或容器不存在） |
| 1 | 命令自身出错 |

## 典型交互

### 微调选中的按钮

用户选中「登录按钮」，说：「改成蓝色，圆角大一点。」

AI 先调用 `bp selection` 取得按钮 id 和当前版本，再提交一次 `apply`，同时修改填充和圆角。成功后画布刷新，这一次修改可以一次撤销。

### 从空画布生成登录页

用户说：「做一个登录页。」

AI 先调用 `bp view` 确认原型范围，再提交一次 `apply`：插入一块登录页画板及其完整子树，为标题、输入框和按钮填写语义化名字，用 `ref` 取得批内引用。后台一次落盘并返回真实 id；AI 用一两句话告诉用户生成了什么，不复述整份 JSON。
