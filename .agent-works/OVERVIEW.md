# DSH Blueprint

一个装在 DeepSeek Harness 里的产品蓝图工具。人和 AI 一边聊，一边在画布上把整个产品的流程做成能点、能改、高保真的蓝图；做完以后，蓝图和设计语言一起交给编码 Agent 实现。

## 目标

在写第一行代码之前，把「这个产品到底怎么用」变成具体的东西：能走通的屏幕、看得见的状态、改得动的细节。

使用者是 Design Engineer、独立开发者，以及要自己动手画蓝图的小团队产品经理。他们不缺想法，缺的是一个能把想法摆上台面、和 AI 逐条对齐的载体。

**做成什么样算成功**：一个没参与讨论的人，打开 DSH、从左侧「蓝图」开始点五分钟，能说出这个产品怎么用、哪一步还没想清楚。他说得出来，就说明蓝图是清楚的。

## 核心概念

| 概念 | 意思 |
|---|---|
| 蓝图 | 核心实体，也是产物本身：一份可被人和 AI 共同编辑高保真界面的设计文档，落成 `.blueprint.json` |
| 设计入口页 | 从左侧「蓝图」进来的中央页面：选工作区、说第一句，发送后开普通会话；不创建蓝图 |
| 蓝图 Dashboard | 管理当前工作区全部蓝图的中央页面，入口按钮写「我的全部蓝图」 |
| 蓝图编辑器 | 会话右侧栏里编辑一份蓝图的界面，标题区显示蓝图名和 id |
| 屏幕 | 一块画布加流程信息。屏幕就是画板，不另设画板概念 |
| 状态 | 同一屏幕在不同情形下的样子，比如默认、空、加载、错误。只存与基础界面的差异 |
| 转移 | 从某个屏幕里的一块，连到另一个屏幕，可以带条件 |
| 动作节点 | 流程里没有界面的步骤，比如发邮件、等审核、支付回调 |
| 设计语言 | 一个 `DESIGN.md` 文件，正文写规则与范例，文末一个 JSON 令牌块 |
| 补丁 | 对设计文档的一次结构化修改。人和 AI 的修改进同一个撤销栈 |

## 关键决定

这些是已经定下来的方向，改动成本高，写在这里方便回看理由。

1. **前端用 React 18。** DSH 的槽位、渲染器和组件库都是 React，跟平台走能省掉一整层适配。
2. **文档是结构化的元素树，布局用 flexbox。** 这样模型能精确改一处，导出的也是能读的 HTML 和 CSS，不是一张图。
3. **模型改文档走结构化补丁，不整份重写。** 整份重写会越改越漂，而且没法局部撤销。
4. **编辑器和导出的 HTML 用同一套 CSS。** 否则编辑器里看着对，导出去不对，等于白做。
5. **设计语言的数字只写一处。** 正文只写名字，不写色值和像素；改一个值只动一处。
6. **令牌变量挂在 `[data-bp-dl]` 作用域，不写 `:root`。** 插件的样式不能漏进宿主界面。
7. **编辑器基座自己写。** 现成库的数据模型都是扁平坐标或 canvas 图形，撑不起盒模型和自动布局。只外挂拖拽手柄、流程总览和撤销栈三件。
8. **开始和编辑分成两种界面，不造专用工作台。** 左侧「蓝图」进设计入口页；发送提示词只开 DSH 普通会话，会话归所选工作区；「我的全部蓝图」进 Dashboard；创建 `.blueprint.json` 才打开右侧编辑器。

## 不做什么

- 不做设计作品生成器。产物是产品蓝图，不是可以直接发布的视觉稿。
- 不做矢量绘图。没有钢笔、布尔运算、蒙版、渐变网格。
- 不做多人协作。第一版只有单人。
- 不做代码生成。蓝图交给编码 Agent，实现方式由它按自己项目的规范决定。
- 不做设计系统市场。设计语言可以导入导出，但没有组件商店。
- 不做独立的「蓝图工作台」主界面，也不为蓝图另造特殊会话类型。

## 怎么参与

如果你是在这个仓库里工作的 Agent，先读根目录的 `AGENTS.md`，它会告诉你怎么认领一张票、产物放在哪、什么该写进 `.agent-works/`、什么只能留在 `.tmp/`。

如果你是人，并且想改点东西：先看一眼路线图，确认要改的那块是不是已经定过了，再动手。
