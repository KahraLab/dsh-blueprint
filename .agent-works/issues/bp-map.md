# DSH Blueprint — 路线图

## Destination

**v1 装进 DSH、真的能用**：一个没参与讨论的人，打开 DSH，从左侧「蓝图」开始点五分钟，能说出这个产品怎么用、哪一步还没想清楚；文档和设计语言落成工作区里的文件，能直接交给编码 Agent 实现。

达到它意味着：剩下的都是实现和打磨，不再有需要产品决策的岔路。

## 实现进度

只在关掉一个里程碑时更新。功能细节看代码和票。

| 里程碑 | 状态 | 到这一步有什么 |
|---|---|---|
| M1 编辑器内核 | 已完成 | 画布、画板、图层、布局、层级树、文档读写、`bp` 命令行 |
| M2 蓝图与存储 | 下一步 | 蓝图列表、按蓝图落盘、打开与新建；顺带补上会话级存储的欠账 |
| M3 生成与聊天迭代 | 待做 | 从一句话生成一屏、对话里逐条改；点选元素写评论 |
| M4 设计语言 | 待做 | `DESIGN.md` 的导入导出、令牌面板、生成时按令牌落样式 |
| M5 流程与状态 | 待做 | 屏幕间转移、只读流程总览、每屏的状态差异 |
| M6 交付 | 待做 | 导出可走查 HTML 与每屏 PNG、快照与版本历史、交接包 |

动某个里程碑之前，先开票把这块还没定的问题解掉；实现本身用 `wayfinder:task` 票。

里程碑怎么切，以「MVP 边界与里程碑」那张票的结论为准；在它关票之前，这张表就是推进用的拆分。

`bp-p1`、`bp-g7` 写在实现之前。认领之前先复核一句：要回答的问题是不是已经被现在的代码越过了。是就撤票，把结论补进 Decisions so far。

## Notes

- **术语**：核心领域实体叫「蓝图」。代码、命令、磁盘目录、界面文案都统一用它，不混用「原型」「项目」这类近义词；旧工作区里的 `prototypes/` 目录、旧的 `current.json` 指针文件与其 `project` 键在读取时就地迁移，不需要手动搬。
- **领域**：DSH（DeepSeek Harness）插件生态。产品是「AI 原生的产品蓝图工具」，给 Design Engineer 用——动工之前与 AI 对齐整个产品的使用流程，并打磨到高保真、可作为编码实现依据的最终态。
- **调研资料**：Claude Design 的产品拆解、DSH 插件的能力边界与未验证项，都在 `.tmp/research/`（本机产物，不进版本库；换台机器就只剩结论，没有原文）。
- **每个 session 先读** `.agent-works/GLOSSARY.md`。涉及决策的票先加载 `grilling` + `domain-modeling` 技能。
- **已定前提**（charting 阶段锁定，不在地图上重开）：
  1. 文档模型 = 结构化元素树 + 盒模型/自动布局，绝对定位作为受限的第二模式。
  2. 模型改文档 = 工具调用 + 结构化 patch；禁止整份重写。工具做成命令行（`bp`），靠 `--help` 渐进披露，不注册成堆原生工具；MCP 是将来套在命令外面的一层壳。
  3. **形态 = 两个中央页面 + DSH 普通会话 + 右侧编辑器。** 左侧「蓝图」进设计入口页；提示词只开普通会话、归入所选工作区；「项目蓝图库」进 Dashboard；创建 `.blueprint.json` 才打开右侧编辑器。点选元素写评论是主交互。
  4. 存储 = 蓝图级 `.dsh-blueprint/`（多设计文件 + 素材 + 历史）。
  5. 核心对象 = 屏幕 + 屏幕间转移 + 每屏状态，附只读流程总览视图。
  6. 保真度 = 高保真；视觉与交互同等重要，可打磨到「拿去编码」的最终态。
  7. 出口 = 设计成果以文件为源，交给编码 Agent 实现（把 Design 与 Artifacts 两条链路并成一条）。
  8. 名字 = **DSH Blueprint**。
  9. MVP 六项：生成、聊天迭代、点选 + 直接操作、设计 token、导出、版本历史。多人协作不做。
  10. **前端实现用 React 18**（平台原生），不使用 Vue。槽位、渲染器、组件库同一套运行时，不引入适配层。
  11. 设计语言是独立的可复用对象：可导入一套现成语言启动蓝图，也可从蓝图沉淀出去。载体与解析细节见票「设计语言的载体与导入导出」。
  12. **蓝图文档文件名统一是 `<名字>.blueprint.json`**：蓝图目录、交接包、导出都用这个格式，单个文件拿出来也认得出是什么。

## Decisions so far

<!-- 每关掉一张票，在这里加一行：- [<票名>](<链接>): <一句话结论> -->

- [编辑器基座选型](bp-r2.md): 基座自研（≈85%），外挂 moveable（自由图层手柄）+ React Flow（只读流程总览）+ zustand/immer（patch 同栈撤销）；tldraw 因许可与扁平坐标模型排除。
- [元素树与样式的表达方式](bp-r3.md): CSS 原生属性对象 + 整值 token 引用；flexbox 薄 IR（hug/fill/fixed）；编译期解析继承；稳定 layer id + 5 个语义 op 做 patch。
- [设计语言的载体与导入导出](bp-g9.md): 单个 DESIGN.md（正文 + 文末 JSON 令牌块）；数字严文字宽；导出器自写；变量只挂 `[data-bp-dl]`。
- [验证 DSH 插件宿主的未验证项](bp-r1.md): 脚手架真实跑通（12.8 KiB，整页 + HMR）；`@Remote` 不可自动化，改用 `ctx.connection.fetch`；CLI Inspect 超时成因已定位。
- [插件架构与存储](bp-g5.md): 后台持权威副本、单一 `apply` 写入口；`connection.fetch` 传输；一个蓝图一个目录；AI 改前自动快照；素材复制进 `assets/`。
- [交接协议](bp-g6.md): 自包含交接包（设计语言 + 蓝图文档 + 每屏参考 HTML + Markdown 实现说明 + 验收清单 + 复述要求），整份蓝图一次交。
- [高保真视觉系统](bp-g3.md): 样式只走令牌；字面值需带理由；八组令牌；硬错拦软错标；八条可自动判断的达标清单。
- [交付物、导出与版本历史](bp-g8.md): 导出为可点击走查 HTML 文件夹 + 每屏 PNG；版本历史用侧边时间线，可预览可恢复；不做 PDF、分享链接、diff。
- [领域模型定稿](bp-g1.md): 屏幕=画板；状态=基础树+差异；转移=显式对象；非界面步骤=动作节点；组件=薄实例；设计语言独立、按版本引用。
- patch 闭环手感蓝图（原票已撤）: 不单独做 mock。真实编辑器已跑通点选、改动、画面刷新；剩下没答的改动动效，移到 Not yet specified。
- [AI 编辑协议](bp-g2.md): 读写统一 JSON，写入统一 `apply`；新增选择与查找；AI 必须起语义名；批内 `ref` 换成真实 id；冲突重读；一次 `apply` 一个撤销单元。
- [AI 读写协议落地](bp-t1.md): 命令面按协议落地，写入只有一个 `change` 入口；字段规则单表驱动画布校验与 `bp schema` 的 JSON Schema；选择状态存在文档旁、不占 revision；`replace` 不再把屏内元素换到画布外层。
- [蓝图与存储](bp-t3.md): 工作区 `.dsh-blueprint/` 是唯一存储，蓝图一个目录一份 `<id>.blueprint.json`；文件带格式版本号，读到更新版本就拒绝；`workspace.json` 记当前蓝图（`lastOpened`），命令行与画布靠它对齐；旧会话文档一次性导入。
- [图标能力](bp-t5.md): 图标集下载到全局 `~/.dsh/blueprint/icons/`；文档里只写集合加名字，系统把 SVG 补进节点，渲染和导出都不依赖网络；选择器只拉选中的集合，网格只渲染看得见的格子。
- [用户故事与核心路径](bp-g10.md): 三条路径（五分钟第一屏 / 一份蓝图走到交付 / 回来接着改），一个循环（说 → 看见 → 指过去 → 改动落下）；v1 必须有十四条故事，验收用陌生人五分钟测试。
- [入口与页面模型](bp-g11.md): 左侧「蓝图」进设计入口页；发送提示词只开普通会话、不建蓝图；「项目蓝图库」进 Dashboard；创建文件才打开右侧编辑器，左栏顶部显示名称和等宽 id；每个会话记住自己的蓝图；Dashboard 打开蓝图借用普通会话。

## Not yet specified

> 在范围内的雾：能感到要来，但还说不成一句精确的问题。等前沿推进到这里，再孵化成票。

- **组件的实例语义**：要不要「改主组件、实例跟随」。倾向要，但取决于领域模型结论；如果做，引用/覆盖/解绑三层语义会显著推高成本。
- **真实数据接入**：蓝图里的列表/详情用假数据，还是能接真实 API / mock server。
- **响应式与多断点**：第一版是否只做单一目标宽度（如 1440），多断点后置。
- **分享与权限**：内部链接、只读分享、评论权限做到哪一层。
- **自定义组件的跨文件复用**：设计语言已独立成票；但用户自定义的组件要不要在多个 Blueprint 之间共享，仍未定。
- **动效**：过渡与微动效是「高保真」的一部分吗，还是纯静态即可。模型改一处时要不要过渡、多快算即时。

## Out of scope

> 明确划出本次 effort 边界的工作。永远不会毕业成票；除非重画 Destination，否则不再回到地图。

- 多人实时协作 / CRDT。
- 矢量路径编辑（钢笔、布尔运算、蒙版、渐变网格）——与已定的盒模型前提冲突。
- 3D 与视频/动效时间轴。
- 跨蓝图全局组件库 / 设计系统市场。
- 移动端原生 App。
- 真实后端与账号体系（Blueprint 是本地文件工具）。
