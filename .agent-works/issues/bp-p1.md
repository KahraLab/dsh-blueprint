## Question

用一份**静态 HTML**（不接任何真实逻辑）把 Blueprint 工作台的信息架构摆出来：屏幕列表 / 画布 / 属性与 token / 流程总览切换 / 对话区。

要回答的是布局与信息密度问题，不是视觉设计：

- 编辑器、流程总览、对话三者怎么共存而不打架？对话是右栏常驻、还是抽屉、还是和画布分屏？
- 多屏幕（手机 + 桌面尺寸）怎么在画布上并排？
- 一个屏幕的多状态（默认/空/加载/错误）在左侧列表里怎么表达，才不至于把列表撑爆？
- 「点选元素 → 评论/改属性」和「对话输入」是同一个入口还是两个？

产出：`prototypes/ia-shell.html`（可直接用浏览器打开）+ 一页说明「为什么这样排、放弃了哪些排法」。
