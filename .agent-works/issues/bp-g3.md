## Question

「高保真」在模型和工具层面靠什么保证？AI 第一版一定不够好，用户要能一路打磨到「可以拿去编码」。

要回答：

- **(a) token 覆盖范围**：颜色 / 字阶 / 间距 / 圆角 / 阴影 / 描边 / 动效 / 栅格，哪些必须有，哪些后置。
- **(b) 编辑入口**：token 用面板调（色板、字阶阶梯、间距尺度）还是聊天调，还是都要；调一个 token 全画布实时预览的机制。
- **(c) 逃生口**：只允许 token 引用（一致性最强、表达力受限），还是允许任意 CSS（自由、但会烂）；如果允许，怎么标记「这个是特例」。
- **(d) 自检**：生成后要不要自动检查对比度、对齐、间距节奏、字号层级；检查结果怎么呈现给用户。
- **(e) 渲染一致性**：编辑器里的渲染和导出的 HTML 必须用同一套 CSS，否则「看着好但导出来不对」。

产出：token schema 草案 + 视觉打磨的交互清单 + 自检规则清单。

## Resolution


2026-10-28 定稿。详见 `.agent-works/specs/visual-system.md`。

- **样式只从令牌来**：图层只存令牌路径，不存数值。
- **字面值允许但要标记**：必须带 `literal: true` 和一句理由；没理由的字面值算硬错误。
- **令牌八组**：颜色、字体组合、间距、圆角、阴影、动效、边框、图标尺寸。透明度用颜色的 alpha 通道表达；层级交给布局系统；栅格后置。
- **检查分两级**：硬错误拦（断链、成环、对比度不达标、无理由字面值）；软问题只标（字号层级超四级、一屏多主按钮、间距不在阶梯、圆角不一致、孤儿令牌、颜色种类过多）。
- **达标用清单**：八条，每条都能被程序判断。
- **渲染一致**：编辑器与导出共用同一份 CSS 文本，用内容哈希断言，不靠肉眼。
- **AI 只输出令牌路径**：硬错误退回给模型自己修，修不好再报给人。
