# 组件、实例与共享资产库

## 1. 背景与目标

蓝图需要一套真正的设计资产复用能力。把图层复制多份只能复制当下结果，无法解决后续统一修改、跨蓝图复用、局部定制和资产维护的问题。

本需求建立完整的组件产品闭环：

- 用户可以把画布中的元素或组合创建为主组件，并在当前蓝图中复用。
- 主组件可以发布为共享资产，供其他蓝图搜索、预览和插入。
- 实例默认持续继承组件定义，同时允许有边界的局部覆盖。
- 组件可以嵌套组合，底层资产能够独立维护和更新。
- 用户与 AI 使用同一套组件语义，不产生只能被其中一方操作的资产。

**北极星：创建一次，随处复用；统一修改，可控同步；局部定制，不中断继承。**

完成标准不是文档中新增了组件节点类型，而是用户和 AI 都能完成「创建 → 复用 → 共享 → 更新 → 定制 → 维护」的完整链路。

## 2. 范围

### 2.1 本需求包含

- 主组件的创建、直接编辑、复制和独立副本创建。
- 本地实例与共享实例的插入、覆盖、重置、回写、嵌套替换和脱离。
- 单一蓝图内的即时联动。
- 跨蓝图的选择性发布、组件库启用、更新审阅和接收。
- 无环嵌套组件及其独立更新链。
- 资产命名分组、描述、搜索、预览、插入和来源导航。
- 组件废弃、来源迁移、来源缺失和恢复。
- 与用户能力等价的 AI / `bp` 操作入口。

### 2.2 非目标

- 组件变体与可配置属性，由 `feat002` 单独定义。
- Design Tokens 的定义与全局联动，由 `feat006` 单独定义。
- 复杂组织权限、审批流和组织级资产治理。
- 完整历史版本浏览器与任意历史版本回滚。
- 发布更新时的像素级前后差异对比。
- 废弃组件的自动迁移。
- 独立的主组件编辑页面。

上述边界不妨碍后续能力复用本 Spec 的稳定身份、引用和发布模型。

## 3. 核心概念

### 3.1 主组件（Main Component）

主组件是组件定义的唯一可编辑真相源。它归属于一个源蓝图，并作为真实设计对象存在于该蓝图的普通画布上。

用户可以像编辑其他图层一样直接选中主组件或其内部节点进行修改。资产面板、预览图和共享库都从不同角度呈现主组件，不构成第二份可编辑定义。

主组件在源画布上的位置不属于共享组件定义。移动主组件不会改变任何实例的位置。

### 3.2 实例（Instance）

实例是对主组件的引用，由以下三部分共同决定最终表现：

1. 当前应使用的组件定义；
2. 仍然有效的局部覆盖；
3. 实例自身的位置与整体变换。

同一蓝图中的实例跟随主组件当前工作定义。跨蓝图实例跟随使用方已经接收的发布版本。

实例不是主组件的普通复制，也不会因为一次局部修改而自动断开引用。

### 3.3 组件库（Component Library）

一个源蓝图可以对外呈现为一个组件库。组件库是该蓝图中已发布组件的共享视图，不是对整份蓝图设计内容的公开复制。

维护者可以选择具体组件发布或更新。使用蓝图必须显式添加组件库，建立可检查的依赖关系后，再从资产面板插入实例。

### 3.4 发布版本（Published Release）

发布版本是主组件在发布时刻形成的不可变共享快照，包含组件结构、默认属性、元数据和嵌套组件引用。

源蓝图中的后续编辑不会自动改变其他蓝图。只有维护者再次发布、使用方接受更新后，跨蓝图实例才切换到新的发布版本。

发布版本用于控制共享资产更新，不是文档并发写入的版本锁。

### 3.5 资产面板（Assets Panel）

资产面板统一承载本地组件和已启用共享组件的浏览与管理，包括：

- 按名称和描述搜索；
- 按分组浏览；
- 查看预览、描述、来源、废弃状态和默认表现；
- 插入实例；
- 转到主组件；
- 查看发布、更新和依赖状态。

## 4. 身份与渲染不变量

### 4.1 稳定身份

- 每个主组件拥有全局稳定且唯一的 `componentId`。
- 主组件内部的每个节点沿用蓝图既有的稳定节点 ID 规则。
- 组件名称、节点名称和分组均不是身份，不得用于匹配覆盖或维持引用。
- 重命名组件或内部节点不得改变其 ID，也不得使已有覆盖失效。
- 主组件跨蓝图迁移时必须保留原 `componentId`。
- 创建独立组件副本时必须生成新的 `componentId` 和新的内部节点 ID。

### 4.2 引用与覆盖寻址

实例通过 `componentId` 找到组件定义。实例覆盖通过「内部节点 ID + 属性键」定位到具体属性。

组件定义更新时：

- 未覆盖属性继承新定义；
- 有效覆盖继续生效；
- 节点被删除后，其覆盖不再参与渲染；
- 后续创建同名节点不会恢复旧覆盖；
- 撤销删除并恢复原节点身份时，可以按撤销事务恢复原有覆盖。

### 4.3 渲染优先级

实例的有效结果按以下顺序计算：

1. 读取当前工作定义或已接收发布版本；
2. 递归解析其中的嵌套实例；
3. 应用仍然有效的实例覆盖；
4. 应用实例自身的整体位置与变换。

任何更新路径都不得通过整棵替换实例的方式抹掉有效覆盖。

### 4.4 无环依赖

组件可以嵌套其他组件的实例，但禁止直接或间接循环引用。

创建组件、插入嵌套实例、替换嵌套实例、迁移主组件和接收更新时，都必须维持这条不变量。会产生循环的操作应被拒绝，并指出形成循环的依赖链。

## 5. 创建、复制与编辑

### 5.1 创建主组件

- 任意单个图层、组合或画板都可以设为主组件。
- 多选时，默认将所选内容组合为一个主组件，而不是批量生成多个组件。
- 创建后，所选内容成为画布上可识别的主组件，原有视觉表现不应改变。
- 创建动作不得把对象移动到独立编辑页，也不要求用户先建立共享库。

### 5.2 直接编辑主组件

主组件及其内部节点可在源蓝图画布中直接编辑。编辑结果立即作用于同一蓝图中的所有实例。

使用共享组件的蓝图不能直接修改远端主组件。用户可以执行「转到主组件」，打开源蓝图并定位到对应对象；编辑后可执行「返回实例」回到原上下文。

### 5.3 复制语义

普通复制保持组件联动：

- 从资产面板插入组件，得到指向该主组件的新实例。
- 复制已有实例，得到指向同一主组件的新实例。
- 普通复制主组件，默认也得到指向该主组件的新实例。

只有显式执行「创建独立组件副本」才生成新的主组件。独立副本拥有新的组件与内部节点身份，之后与原组件互不影响。

### 5.4 跨蓝图复制实例

将实例复制到另一份蓝图时，必须保留原组件引用：

- 目标蓝图已启用来源组件库时，直接建立同引用实例。
- 尚未启用时，引导用户添加来源组件库。
- 不得静默复制成独立主组件，也不得静默脱离为普通图层。

## 6. 实例覆盖与结构边界

### 6.1 可覆盖内容

首版支持以下覆盖类别：

- 文本内容；
- 字体与文本样式；
- 填充、描边、不透明度；
- 阴影、模糊与圆角；
- 内部图层名称；
- 实例整体位置、尺寸与变换；
- 嵌套实例替换。

覆盖只影响当前实例，不自动改变主组件或其他实例。

### 6.2 实例整体与内部布局

实例的整体位置和尺寸独立于主组件：

- 主组件在源画布中的坐标不传播到实例；
- 每个实例可以独立摆放；
- 整体尺寸被修改后记为实例覆盖；
- 实例内部节点的布局默认继续继承主组件。

### 6.3 结构锁定

普通实例不允许直接进行以下操作：

- 增加或删除内部节点；
- 重排内部节点；
- 修改内部节点位置或层级顺序；
- 以其他方式改变组件内部结构。

需要改变所有实例的结构时，应编辑主组件。只需要一个独立结构时，可以脱离实例。

替换已有嵌套实例属于受支持的覆盖，不视为任意增删内部节点。

### 6.4 重置覆盖

用户可以：

- 重置单个属性；
- 重置某个内部节点的全部覆盖；
- 重置整个实例的全部覆盖。

重置后，对应内容恢复继承当前主组件定义。重置操作本身可以作为撤销事务恢复。

### 6.5 将覆盖回写主组件

提供显式的「将覆盖应用到主组件」操作：

- 仅支持实例与主组件位于同一源蓝图的情况；
- 用户明确选择需要回写的覆盖；
- 回写后，主组件及其他实例按正常联动规则更新；
- 跨蓝图实例必须转到源蓝图编辑，不能直接回写远端主组件；
- 不得在编辑实例时自动回写。

### 6.6 脱离组件

脱离后，系统按当前有效表现生成普通图层树，原实例引用和覆盖关系不再保留：

- 不再接收主组件更新；
- 不能重新连接原主组件；
- 误操作只能通过立即撤销恢复；
- 执行前必须明确反馈其后果。

## 7. 嵌套组件

### 7.1 自由组合

主组件可以包含其他组件的实例。例如，`Card` 主组件可以包含 `Button` 和 `Icon` 实例。

底层组件更新后，所有引用它的实例按各自所在蓝图的同步规则更新，包括嵌套在其他主组件中的实例。

### 7.2 独立更新链

底层组件可以独立发布和接收更新，不要求外层组件重新发布。

例如，使用方接受新的 `Button` 发布版本后，`Card` 内嵌套的 `Button` 同步更新；只有 `Card` 自身结构、默认属性或直接覆盖发生变化时，才需要发布新的 `Card` 版本。

外层发布版本保存对底层组件的引用及其所需发布版本，不得把底层组件复制成一份脱离来源的私有定义。

### 7.3 嵌套实例替换

外层组件的实例可以替换其内部已有的嵌套实例，例如把 `Info Icon` 换成 `Warning Icon`。

- 替换记录为外层实例的覆盖；
- 替换不影响主组件和其他实例；
- 替换后的组件仍遵循自身更新规则；
- 替换不得制造循环依赖；
- 重置该覆盖后恢复主组件默认嵌套实例。

## 8. 发布、启用与更新

### 8.1 发布组件

维护者可以从源蓝图中选择一个或多个组件进行发布：

- 新组件发布后进入共享资产面板；
- 已发布组件的后续修改先保留为未发布变更；
- 再次发布时，可填写本次更新说明；
- 未被选择的组件和蓝图中的其他设计内容不因本次操作而共享；
- 发布只生成共享快照，不改变源蓝图工作定义。

### 8.2 启用组件库

目标蓝图显式添加来源组件库后：

- 记录来源依赖；
- 共享组件出现在资产面板中；
- 用户可以搜索、预览和插入实例；
- 实例记录已接收的发布版本。

移除组件库不得删除目标蓝图中的已有实例。已有实例保留最后可用表现并显示来源状态，重新启用后可恢复更新链路。

### 8.3 审阅与接收更新

来源组件再次发布后，目标蓝图显示待更新状态。使用方可以查看：

- 哪些组件存在更新；
- 本次发布说明；
- 当前版本与待接收版本标识；
- 当前蓝图中受影响的实例。

使用方可以更新单项或全部。接收后，目标蓝图中的所有相关实例切换到对应发布版本，并按有效覆盖规则重新计算表现。

本需求不要求像素级差异对比，但更新数量和影响范围必须可见。

### 8.4 不自动接受共享更新

跨蓝图更新不得因源蓝图保存、AI 修改主组件或打开目标蓝图而自动生效。只有用户明确接受，或用户明确指示 AI 执行接受操作时，才切换发布版本。

## 9. 资产生命周期管理

### 9.1 命名、分组与描述

- 组件可以重命名，不影响引用和覆盖。
- 使用一致的层级名称表达分组，例如 `Navigation/Sidebar`。
- 描述用于说明用途、使用约束和搜索关键词。
- 搜索同时匹配名称与描述。
- 预览由组件定义生成，不要求维护者另存一张图片作为真相源。

### 9.2 废弃

组件可以被标记为废弃，并填写废弃说明与推荐的替代组件：

- 已有实例保持原样，不自动替换；
- 新插入时显示废弃提醒与替代建议；
- 用户仍可因兼容需要继续使用；
- 废弃状态随发布和更新流程传播。

### 9.3 迁移主组件

已共享主组件可以迁移到另一个源蓝图：

- 保留 `componentId` 和内部节点身份；
- 保留现有实例引用与有效覆盖；
- 原来源与新来源的变更通过发布、接收流程对使用方可见；
- 迁移不得生成同名但不同身份的重复资产；
- 迁移后仍需维持无环依赖。

### 9.4 删除与来源缺失

删除主组件、来源蓝图暂不可用或组件库被移除时，已有实例不得被连带删除。

实例保留最后一次可用定义或发布版本的只读渲染快照，并明确显示来源异常。快照只用于保底渲染，不是可编辑的第二真相源。

用户可以按情况执行：

- 恢复原 `componentId` 的主组件；
- 将实例替换为其他组件；
- 脱离为普通图层；
- 重新启用或定位来源组件库。

恢复主组件必须恢复原引用关系，不能借恢复之名创建无关的新组件。蓝图删除仍遵循项目既有的回收站规则。

## 10. 界面与反馈

### 10.1 对象识别

主组件与实例必须在画布和图层面板中具有可区分但一致的图标、边界或标记。

以下状态必须可见：

- 主组件；
- 实例；
- 存在局部覆盖；
- 存在待接收更新；
- 来源缺失；
- 已废弃。

状态反馈不得只依赖颜色，并应满足项目既有的键盘访问、焦点可见和可访问名称要求。

### 10.2 来源与依赖导航

选中实例时，用户可以：

- 查看组件名称、来源蓝图和当前发布版本；
- 转到主组件；
- 返回原实例；
- 查看当前蓝图启用的组件库及相关依赖；
- 查看待更新和来源异常的处理入口。

### 10.3 属性栏反馈

属性栏需要区分继承值与覆盖值，并提供对应重置入口。结构锁定的原因应在用户尝试增删或重排内部节点时得到明确解释，而不是让操作无响应。

## 11. 用户与 AI 的完整闭环

用户和 AI 必须共享同一套领域规则与操作能力。AI 通过项目既有的 `bp` 命令行入口读写蓝图，插件本体不得调用大模型或拼装提示词。

AI 应能完成：

- 创建主组件和独立组件副本；
- 插入、复制和替换实例；
- 编辑主组件；
- 设置、读取和重置覆盖；
- 将同蓝图覆盖回写主组件；
- 脱离实例；
- 发布组件、启用组件库和审阅依赖；
- 接收单项或全部更新；
- 标记废弃、迁移主组件和处理来源异常。

发布会改变共享资产、接收更新会改变其他蓝图中的组件表现，脱离会永久断开引用。这些操作必须由用户明确指示，AI 不得在后台自行执行。

AI 与用户操作都不能绕过稳定身份、结构锁定、无环依赖和发布接收规则。`bp` 应提供结构化结果与明确错误，而不是依赖界面 scrape 或模拟鼠标完成领域操作。

## 12. 技术落地契约

### 12.1 单一文档与共享引用

每份蓝图仍由自己的单一 JSON 文档承载。共享组件库不会把多份蓝图合并成一个文件，也不会要求目标蓝图复制完整源文档。

源蓝图保存主组件工作定义与已发布组件信息；使用蓝图保存组件库依赖、组件引用、已接收发布版本、实例覆盖和必要的只读保底快照。

### 12.2 领域层职责

纯领域层负责：

- 组件与实例身份；
- 引用解析和覆盖合并；
- 结构边界校验；
- 嵌套依赖与循环检测；
- 发布版本切换；
- 生命周期状态转换。

领域规则不得依赖 React、浏览器或 Node 文件系统。画布、属性栏、资产面板和 `bp` 必须复用同一套应用服务，不得分别实现一套合并规则。

### 12.3 渲染与缓存

工作定义和发布版本是组件定义的权威来源。预览图、解析后的嵌套树和来源缺失时的保底快照均为派生数据，不得被独立编辑。

来源恢复后，系统按权威定义、已接收发布版本和有效覆盖重新计算，而不是把缓存反向写回主组件。

### 12.4 写入与并发

组件功能继续遵循项目既有约束：

- 写入不加锁，按最后写入者生效；
- 按节点 ID 进行增量合并；
- 使用结构化补丁，不整份重写蓝图；
- 插入或移动组件定义时保全完整子树；
- 发布版本不用于拦截并发写入，也不引入版本冲突锁。

## 13. 关键边界行为

- **主组件移动位置**：只改变源画布摆放，不改变实例位置。
- **主组件重命名**：资产展示更新，引用与覆盖保持不变。
- **主组件删除内部节点**：该节点及其覆盖不再渲染，其他有效覆盖继续保留。
- **更新命中已覆盖属性**：保留实例覆盖，不用主组件新值强行覆盖。
- **目标蓝图暂不接收更新**：继续按已接收版本渲染，源蓝图后续编辑不影响它。
- **底层嵌套组件更新**：无需重新发布所有外层组件，接受底层更新后递归生效。
- **复制共享实例到未启用来源的蓝图**：保留引用并引导添加依赖，不静默脱离。
- **组件库不可用**：已有实例按保底快照渲染并显示异常，不清空画布。
- **废弃组件**：已有实例不变，新插入显示提醒，不自动迁移。
- **循环嵌套**：操作被拒绝并说明依赖链。
- **普通复制与独立副本**：前者保持引用，后者创建新身份，二者不可混用。

## 14. 自测与验收路径

本需求采用真实 CLI 调用和浏览器交互验收，不新增自动化测试套件。

### 14.1 本地组件闭环

1. 在画布选择多个图层并创建一个主组件。
2. 普通复制主组件，确认得到联动实例。
3. 修改主组件，确认所有同蓝图实例即时更新且实例位置不被重排。
4. 修改一个实例的文本、样式和整体尺寸，确认其他实例不变。
5. 再修改主组件，确认未覆盖属性同步、已覆盖属性保留。
6. 分别按属性、节点和整个实例重置，确认继承恢复。
7. 将部分覆盖回写主组件，确认其他实例按规则更新。
8. 脱离一个实例，确认其不再联动，其他实例不受影响。
9. 创建独立组件副本，确认新旧主组件身份和后续修改完全独立。

### 14.2 嵌套组合闭环

1. 创建 `Button`、`Card` 两个主组件，并在 `Card` 中嵌套 `Button` 实例。
2. 修改 `Button`，确认本地 `Card` 及其所有实例中的按钮同步更新。
3. 在某个 `Card` 实例中替换嵌套组件，确认替换被记为局部覆盖。
4. 重置替换，确认恢复默认嵌套组件。
5. 尝试构造直接与间接循环，确认操作被拒绝且已有文档未损坏。

### 14.3 跨蓝图共享闭环

1. 从源蓝图选择性发布组件，确认未选内容不会进入共享库。
2. 在目标蓝图启用来源库，搜索、预览并插入实例。
3. 修改源主组件，确认目标蓝图在发布前不出现待接收变化。
4. 发布更新，确认目标蓝图显示更新说明和受影响实例。
5. 分别验收单项更新与全部更新，确认目标实例切换到新发布版本。
6. 确认有效覆盖在更新后保留，已删除内部节点的覆盖按规则失效。
7. 更新底层嵌套组件，确认无需重新发布外层组件即可在接受更新后生效。
8. 跨蓝图复制实例，确认引用保留且依赖添加路径明确。

### 14.4 生命周期与管理闭环

1. 验收命名分组、描述搜索、预览、来源导航和依赖查看。
2. 标记组件废弃并设置替代建议，确认已有实例不变、新插入有提醒。
3. 将共享主组件迁移到另一源蓝图，确认组件身份、实例引用和覆盖保持。
4. 删除主组件、移除组件库或使来源暂不可用，确认已有实例仍可渲染且异常可见。
5. 分别走通恢复来源、替换组件和脱离实例的处理路径。
6. 重新打开相关蓝图，确认引用、发布版本、覆盖和状态均正确持久化。

### 14.5 AI 与工程验收

1. 使用真实 `bp` 命令完成创建、插入、覆盖、重置、嵌套替换、发布、接收和生命周期操作。
2. 确认 AI 与画布操作同一份文档时，双方看到一致的组件关系与最终表现。
3. 确认未经明确指示，AI 不会自行发布、接收共享更新或脱离实例。
4. 确认插件没有新增模型调用或提示词拼装。
5. 完成 `pnpm -C apps/plugin typecheck`、`pnpm -C apps/plugin i18n:check` 和 `pnpm -C apps/plugin build`。
6. 在真实浏览器中走查上述核心链路、状态反馈、键盘访问和撤销重做，不以编译通过代替产品验收。

只有以上用户闭环、AI 闭环和异常恢复路径均可实际执行，本需求才具备独立验收条件。
